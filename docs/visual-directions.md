三套视觉，**同一个组件层**。切换 = 换一层 token，不改任何组件、不 fork 代码。

- 单文件里右上角 **◧ 编辑部 / 控制台 / 高饱和** 循环切换（快捷键 `S`），`◐` 切深浅。
- 也可以直接开钉死皮肤的三个文件：`grill-demo-paper.html` / `-terminal.html` / `-bold.html`。
- 任意状态加 hash：`#skin=terminal&theme=dark&screen=wb&round=3`

## 调研结论（2026）

四条对我们直接适用：

1. **信任本身成了 AI 产品的设计问题。** NNGroup 的 State of UX 2026 把它列为今年 AI 产品最大的设计难题，给的处方是「show your work, provide sources, let users verify」——这恰好就是我们已经在做的三色出处。所以视觉风格的第一职责是**让证据看起来可核对**，而不是让稿子看起来漂亮。
2. **AI 徽章消失了，智能变成了基础设施。** 2026 年做得好的产品把 AI 字样埋掉，不再靠"AI"两个字获取注意力。→ 三套皮肤里我都没有加任何发光/渐变/星星之类的「AI 感」装饰。
3. **muted minimalism 正在被 bold visual systems 取代**：饱和色、表达型字体、可复用的标志性 UI 图形，目的是品牌记忆。→ 这是方案 C 的依据。
4. **等宽 / 控制台美学**（Vercel 一脉）在数据密集型工具里仍然是可信度信号；但要注意「潮流野兽派」2026 年 3 月见顶后在退，**功能性的那一支才是长青的**。→ 方案 B 走功能路线，不做造型秀。

另外两条排版趋势：高对比编辑型衬线在回潮（用于标题和编辑语境），以及「neo-serif 标题 + mono 数据」的搭配在高端产品里很常见。

## 三套方案

三套在四个轴上被刻意拉开：**标题字族 / 密度 / 形状 / 色彩策略**。

| | A · 编辑部 | B · 控制台 | C · 高饱和 |
|---|---|---|---|
| 标题字族 | Georgia / 宋体（衬线） | 等宽 | 系统无衬线 800 字重 |
| 卡片圆角 | 16px | 3px | 20px |
| 阴影 | 有，柔和 | **无**（只有发丝线） | 有，带品牌色 |
| 底色 | 暖纸 `#F7F5EF` | 纯白 / 纯黑 | 冷紫 `#F6F4FF` |
| 主按钮 | 墨色 | 墨色 | **品牌紫 `#4C1DD9`** |
| 小标签 | 正常大小写 | **全大写 + 宽字距** | 正常 |
| 它在说什么 | 「这是一份文档，可以核对」 | 「这是一台仪器，数据密集是优点」 | 「这是一个有主张的产品」 |

### A · 编辑部（默认）
衬线标题、暖纸底、留白更松，正文行高 1.85。原文/自我介绍也走衬线——因为它们本来就是**要被人读的散文**，不是 UI 文本。`RESUME · NETWORKING` 那行 kicker 改成斜体衬线。

**赌的是**：这个产品的核心是「可核对」。编辑部气质天然带着「有编辑、有事实核查」的暗示，和三色出处是一套话。

**代价**：不像一个"AI 产品"，在一堆蓝紫渐变的竞品里可能显得保守。中文衬线在 Windows 上的回退字体不可控。

### B · 控制台
所有 UI 铬件（按钮、标签、面板标题、计数）走等宽，正文保持无衬线以便阅读。圆角几乎归零，连 pill 都是 2px。**阴影全部去掉**，层次只靠发丝线。小标签全大写 + 1.8px 字距。深色版是纯黑 `#000`。

**赌的是**：我们的界面本来就数据密集——五个面板、要求清单、维度矩阵、四种计数。控制台美学不是给它化妆，是**承认它是什么**。

**代价**：对非技术用户（正在焦虑投简历的学生）可能显得冷、显得难。这是三套里最挑受众的。

### C · 高饱和
品牌紫做主按钮和强调色，标题 800 字重、-1.2px 字距、46px。卡片有实体阴影。hero 用紫→暖橙的渐变。

**赌的是**：「AI 改简历」这个赛道极度同质化，视觉记忆点本身就是护城河的一部分。

**代价**：紫色和我们的三色出处（蓝/金/红）共处一个画面时，颜色总量偏多。我把品牌紫限制在**按钮和交互态**，不进入内容区，就是为了不和出处颜色抢。这条约束如果被破坏，整套就会糊。

---

## 一条不能动的底线

三套皮肤里，**蓝 / 金 / 红三色出处的语义不能变**：蓝＝来自你已有的材料，金＝刚从你嘴里挖出来的，红＝AI 补的待确认。已经写成断言：三套 × 深浅两种主题共 6 个组合下，三色的实际合成背景色**互不相同**。

配色可以换，语义不能换——它是这个产品的地基，不是装饰。

---

## 实现方式

之前的组件层已经全部走语义变量，这一版又补了两组：

- **形状**：`--r1 … --r5 --rp` 五档圆角。原来 123 处硬编码圆角全部换成了 token 引用，所以「圆角语言」是一个可换的整体。
- **排版**：`--display`（标题字族）、`--h-weight`、`--h-track`、`--lbl-track`、`--lbl-case`。

于是一套皮肤 = 一个 `[data-skin="x"]` 块（浅色）+ 一个 `[data-skin="x"][data-theme="dark"]` 块（深色）+ 十来行结构性微调。**没有任何组件代码被 fork。**

## 已验证

- 3 套皮肤 × 深浅 2 种主题 = **6 个组合全部实测**：正文 / 次要文字 / 问题 / 账本条目 / 金色标签 / 把握证据 / 要求清单，七类文字的合成对比度**全部 ≥ 4.5:1**。
  顺带修掉了之前一直挂着的那个「11px 次要文字浅色 4.2:1」——现在三套皮肤都达标了，**没有遗留未达 AA 的项**。
- 三套的圆角 / 标题字族 / 阴影三项实测互不相同（16px·Georgia·有 ／ 3px·等宽·无 ／ 20px·系统·有）。
- **112 条功能回归断言全绿**，0 个 JS 错误——换皮肤没有碰任何逻辑。

## 我的建议

**先用 A 上线，把 B 留作一个可切换的选项。**

理由：目标用户是正在焦虑投简历的学生，A 最不吓人，而且它和「可核对」这个核心主张是同一套语言。B 太挑受众，但它对**给导师/投资人演示**特别有效——数据密集在控制台皮肤下看起来是能力，在纸面皮肤下看起来是复杂。既然切换成本已经是零，不如两套都留着。

C 我做完之后自己不太推荐现在用：它的品牌记忆点是靠颜色堆出来的，而我们真正的记忆点应该是**三色出处**这个机制本身。等出处这套视觉语言被人记住了，再考虑要不要加一层品牌色。
