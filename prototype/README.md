## A-1 · 两种投喂方式

投喂页顶部是一个二选一：

**方式 A｜我有一段想改的经历** — 粘一段自己写的，它成为最后对比用的基准。（原来的路径）

**方式 B｜从我的材料里挑一段** — **一个字都不用写**。系统先把 12 条 crumbs 聚成几段「能讲的经历」，每段给出：

- 它是**聚自哪几条材料**（材料名直接列出来，可核对）
- **材料厚 / 中 / 薄**，以及缺口在哪（「6 条材料里有代码、有事故、有吵架记录，却没有一条写了结局」）
- 预计能问出几轮

选中之后会明确告诉你：**这段基准是从材料里拼的，不是你写的**。所以成果页的对比口径也跟着换——不是「你写的 vs 成稿」，而是「**材料里本来有的 vs 问出来之后的**」，BEFORE 栏直接列出那几条材料原文。

> 原型里只有第一段有拷问脚本（6 轮问答是手写假数据），另外两段选中后会禁用「开始」并说明原因，不假装能跑。

## A-2 / A-3 · 工作台改成四面板

顺序就是你要的：**材料 — 拷问 — 简历活稿 — 收获账本**。

**每个面板三态**：正常 / 收成边上的竖条（带竖排标签和计数）/ ⤢ 放大顶开其他。顶部有一条**面板条**，四个开关一字排开，显示当前状态；面板条自己也能收起（▲）。窄屏会按优先级自动收，但你手动点过的面板不会被自动改。

**材料面板独立出来了**，分两组：**本场使用中** / **材料库·没进本场**。卡片可以在两组之间**拖**，也能点 ±。

这里加了一个原来没有的因果：**把材料拖出本场，引用它的句子当场变红并标「出处已移出」**，计数从「有材料出处」挪到「无出处」。这不是装饰——它和后端 schema 里 `source_needs_crumb` 那条约束是同一件事：出处没了，那句话就不再算有出处。

**收获账本和 Thread 成果合并了**，就在最右侧一个面板里。你说得对，它们本来就是同一份数据，而且旧的 Thread 视图把左边已经显示过的问题又抄了一遍。

现在的账本：

- **栏目 = matrices**，可切 **按维度** / **按标签**。按维度是固定六栏（空栏保留，因为「这场没问到这个角度」本身是信息）；按标签是动态栏目（`#数字` `#取舍` `#冲突` `#业务指标`…），只出现有内容的栏。
- 每条只标 **「第 N 轮 ↗」**，**不复述问题**。点它会展开左边的拷问面板并把那一轮滚动到视野中央、高亮一下。
- 候补条目是金色虚线卡片，可直接拖进简历面板。

## B · Dashboard 重做

你的直觉是对的，我认为原因是：**「拷问记录 / 事实库 / artifact / 候补」是我们的数据模型，不是用户的心智。** 用户不会想「我有 3 个 thread 和 24 条 fact」，他想的是「我有几段能拿去讲的经历，哪段够厚了，哪段还很薄」。

所以这一版按**经历**组织。每张卡是一段经历：

- **六格维度矩阵** —— 填了几格是数出来的（每格是该维度下的事实条数），空格＝这段还没被问到那个角度。仍然没有百分比。
- 一行可数指标：材料 N 条 · 事实 N 条 · 维度 N/6 · 问过 N 轮
- 它**喂了哪几份稿子**（没有就明说「还没喂给任何一份稿子」）
- 展开可以看这段的全部事实，按维度分组

然后两条次级货架：**产出物**（每份标明由哪几段经历喂出来 + 三色出处条）和**材料**（原料层，同一条材料可以喂多段经历）。

对你那几个"什么才算资产"的问题，我的判断是：

- **经历是资产** —— 它是用户能带走、能复用、能一直加厚的东西。
- **产出物是快照** —— 简历 v3 是某个时点从经历里取的料，它会过期。
- **材料是原料** —— 是输入，不是成果。
- **拷问记录不是资产，是过程** —— 它退成了经历卡上的「问过 N 轮」和每条事实的「第 N 轮 ↗」。单独给它一个顶层分类，就等于让用户管理我们的日志。
- **事实库确实不该是顶层分类** —— 你的犹豫是对的。一条孤零零的事实没有意义，它只有挂在某段经历下才有意义。所以事实降级成经历卡里的内容。

**候补也不再是分类，而是待办。** 顶部一条待办栏：「N 条候补事实还没进任何稿子 · N 段经历问到一半」，带直达按钮。名词按心智分（经历/产出物/材料），动作按待办列——这是这一版的组织原则。

> 这仍然是一个提案。如果你觉得「经历」这个单位太重（比如有人就是想改一条 bullet，不想先建一段经历），另一条路是**以产出物为中心**：Dashboard 就是几份简历，事实和经历都藏在简历下面。我没选它，是因为那样事实就很难跨简历复用——而复用是这个产品最值钱的部分。
